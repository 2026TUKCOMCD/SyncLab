# 📋 Multi-View Sports Editing System 제품 백로그 (Product Backlog)

본 문서는 대학교 4학년 졸업작품으로 개발하는  
**다각도 스포츠 경기 촬영 및 편집 웹 시스템**의 Product Backlog이다.

시스템 흐름은 다음과 같다.  
촬영(App) → 인제스트 & 가공(Server) → 편집(Web) → 렌더링(Server)

---

## 1. 🥇 핵심 기능: 촬영 및 시간 동기화 (Mobile App)

본 섹션은 **멀티뷰 편집의 정확성(Goal)** 을 결정하는 핵심 기능으로  
모든 기능은 **MVP 필수 (High Priority)** 로 분류한다.

| ID | 사용자 스토리 | PRD / 기능 | 개발 영역 | 우선순위 |
|:---|:---|:---|:---|:---|
| MA-101 | 촬영자로서 모든 기기의 시간을 동일한 기준으로 맞추고 싶다 | NTP 서버와 통신하여 기기 시간 Offset 계산 | Android/iOS | 1 |
| MA-102 | 촬영 시작 시 정확한 절대 시간을 기록하고 싶다 | 녹화 시작 시 NTP 기준 Timestamp 메타데이터 생성 | Android/iOS | 1 |
| MA-103 | 고화질 영상을 서버로 안정적으로 업로드하고 싶다 | 1080p 영상 분할 업로드 및 재전송 처리 | Android/iOS | 1 |
| MA-104 | 프로젝트에 참여하기 위해 초대 코드를 입력하고 싶다 | 6자리 코드 입력 및 QR 스캔 UI | Android/iOS | 2 |
| MA-105 | 촬영 및 업로드 상태를 직관적으로 확인하고 싶다 | 녹화/업로드 진행 상태 UI | Android/iOS | 3 |

## 2. 🥈 인제스트 및 프록시 영상 생성 (Backend Server)

편집 성능과 데이터 신뢰성을 좌우하는 **서버 핵심 처리 영역**이다.

| ID | 사용자 스토리 | PRD / 기능 | 개발 영역 | 우선순위 |
|:---|:---|:---|:---|:---|
| BE-201 | 서버로서 업로드된 영상을 안전하게 저장하고 싶다 | 영상 수신 및 저장 경로 자동 관리 | FastAPI | 1 |
| BE-202 | 각 영상의 촬영 정보를 체계적으로 관리하고 싶다 | NTP 시간, 카메라 ID, 경로 DB 저장 | Backend/DB | 1 |
| BE-203 | 웹 편집을 위해 가벼운 영상을 제공하고 싶다 | FFmpeg 기반 Proxy 영상 생성 | Backend | 1 |
| BE-204 | 다수의 영상 처리를 동시에 수행하고 싶다 | Celery + Redis 비동기 작업 큐 | Backend | 2 |

## 3. 🥇 핵심 기능: 멀티뷰 웹 편집 (Web Frontend)

본 섹션은 **사용자가 직접 사용하는 핵심 UX 영역**으로  
졸업작품 시연의 중심이 되는 기능이다.

| ID | 사용자 스토리 | PRD / 기능 | 개발 영역 | 우선순위 |
|:---|:---|:---|:---|:---|
| WF-301 | 여러 각도의 영상을 동시에 보고 싶다 | 4분할 멀티뷰 플레이어 | React | 1 |
| WF-302 | 영상들이 시간상 정확히 맞춰서 재생되길 원한다 | NTP 기반 Offset 계산 및 싱크 재생 | React | 1 |
| WF-303 | 카메라 전환만으로 편집을 구성하고 싶다 | 컷 편집을 EDL 데이터로 기록 | React | 1 |
| WF-304 | 영상의 일부만 사용하거나 속도를 조절하고 싶다 | Trim / Speed 정보 EDL 관리 | React | 2 |
| WF-305 | 편집 상태를 되돌리거나 유지하고 싶다 | EDL 상태 관리 (Zustand) | React | 2 |
