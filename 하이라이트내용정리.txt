1. 결정된 방식: 비전 기반 AI 분석 (YOLOv8 + OpenCV)
━━━━━━━━━━━━━━━━━━━━━━━━

[교체 이유]
- 소규모 경기장 특성상 경기 내내 환경 소음이 높음
  (관중 소리, 에코, 음악 등이 상시 혼재)
- 오디오 기반(librosa)은 득점 후 함성 급증을 신호로 쓰는데,
  배경 소음이 고르게 높으면 피크 구분이 불가능
- 반면 영상에서 선수의 신체 움직임은 소음과 독립적으로 관찰 가능

[선택 방식]
- 1차: YOLOv8 농구공 추적 + 포물선 궤적 감지 (슛 동작 직접 인식)
- 폴백: 시각적 동작 에너지 패턴 분석 (선수 움직임 변화)

[의존성 변경]
- 제거: librosa, scipy.signal (오디오)
- 추가: ultralytics (YOLOv8), opencv-python
- 유지: numpy, scipy.ndimage (스무딩), scipy.signal (피크탐색)

2. 알고리즘 설명
━━━━━━━━━━━━━━━━━━━━━━━━

[단계별 흐름]

  ① 비디오 단일 패스 (5fps 샘플링)
     - YOLOv8 nano 모델로 COCO class 32 (sports ball) 감지
     - 동시에 320×180 소형 프레임 차이값으로 동작 에너지 계산
     - 메모리 효율: 프레임을 저장하지 않고 처리 후 버림

  ② 공 궤적 추적
     - 연속 감지 위치를 하나의 궤적으로 묶음
     - 1.5초 이상 감지 공백 발생 시 궤적 분리
     - 최소 4프레임 이상인 궤적만 유효 처리

  ③ 포물선 궤적 감지 (1차 방법 — 직접 슛 인식)
     조건:
       a. 궤적 내 y 최솟값(화면 최고점)이 양 끝 사이 중간에 위치
          → 진짜 포물선 아치 (상승 후 하강하는 슛 동작)
       b. 아치 정점이 화면 상단 45% 이내
          → 농구 골대 높이 범위에서의 슛
       c. 정점 전후 y 변화량이 7% 이상
          → 단순 수평 이동이 아닌 실제 슛 탄도

  ④ 동작 에너지 패턴 감지 (폴백 — 공 추적 실패 시)
     - 득점 직후 선수들이 잠시 멈추는 패턴을 시각적으로 탐지
       (하이파이브, 자축, 공 회수 등)
     - 동작 에너지 '급감 → 회복' 패턴의 저점이 득점 순간으로 추정
     - 신뢰도는 최대 60으로 제한 (직접 감지보다 낮게)

  ⑤ 빌드업 시작점 탐색
     - 득점 시점에서 최대 20초 뒤로 소급
     - 동작 에너지가 기준선(35번째 백분위수 × 1.4) 이하인
       '마지막 조용한 순간'을 찾음 → 공격 플레이 시작점
     - 결과:
       역습(fast break): 빌드업 3~7초
       세트 플레이:       빌드업 8~18초

  ⑥ 클립 구간 결정
     - 시작: 빌드업 시작점
     - 종료: 득점 순간 + 2.5초
     - 최소 1초 미만 클립 제거

  ⑦ 결과 반환
     - 민감도 필터 → 중복 병합 → 신뢰도 순 상위 25개 → 시간 순 정렬

[백엔드 (FastAPI + Python)]

  파일: synclab-backend/app/services/ai_highlight.py
  클래스: BasketballHighlightDetector
  의존성: ultralytics >= 8.0, opencv-python >= 4.8, numpy >= 1.24.0
          scipy >= 1.11.0

  API 엔드포인트: (변경 없음)
    POST /api/web/ai_highlight
      → 분석 작업 시작, job_id 즉시 반환 (백그라운드 처리)
    GET  /api/web/ai_highlight/stream/{job_id}
      → SSE로 진행률 스트리밍 (0→100%)
      → 완료 시 highlights 배열 포함하여 반환

  응답 형식 (highlights 항목): (변경 없음)
    {
      "id": "goal_0",
      "index": 1,
      "timestamp": 45.3,        // 득점 순간 (비디오 내 초)
      "start": 32.1,            // 빌드업 시작 (비디오 내 초)
      "end": 47.8,              // 클립 종료 (비디오 내 초)
      "duration": 15.7,         // 총 클립 길이 (초)
      "buildup_duration": 13.2, // 빌드업 구간 (초)
      "confidence": 87,         // 신뢰도 (0~100%)
      "type": "scoring_play"
    }

[조정 가능한 파라미터]
  sensitivity (기본 0.85):
    - 올리면 → 감지 수 감소, 정확도 상승
    - 낮추면 → 감지 수 증가, 오탐 가능
  ARC_PEAK_ZONE (기본 0.45): 화면 상단 몇 %까지 슛 정점으로 인정
  MIN_ARC_HEIGHT (기본 0.07): 포물선 최소 높이 (낮추면 더 많이 감지)
  MAX_BUILDUP_SEC (기본 20초): 최대 빌드업 소급 시간
  POST_SCORE_SEC (기본 2.5초): 득점 후 포함 시간
  MIN_GOAL_GAP_SEC (기본 8초): 연속 득점 최소 간격

5. 한계 및 향후 개선 방향
━━━━━━━━━━━━━━━━━━━━━━━━

[현재 한계]
- YOLOv8 COCO 모델은 저화질·원거리 농구공에서 감지율이 낮을 수 있음
  → 공 감지 실패 시 자동으로 동작 에너지 폴백 사용
- 카메라가 골대를 측면이 아닌 후방에서 촬영할 경우 포물선 감지 어려움
- 분석 대상이 1개 카메라(첫 번째)로 고정

[향후 개선]
- 농구공 전용 파인튜닝 모델로 감지율 향상
- ByteTrack 등 멀티오브젝트 트래킹 적용 (공 연속성 강화)
- 골대 영역 자동 감지 → 공+골대 교차 확인으로 정확도 대폭 향상
- 선수 자세 추정(MediaPipe Pose)으로 팔 들기(함성) 동작 보조 신호 추가
- 사용자가 분석할 카메라를 직접 선택하는 UI 추가
- sensitivity를 UI에서 조정 가능하도록 슬라이더 추가

6. 멀티카메라 하이라이트 구성 전략 (2026-07-06 추가)

[카메라 배치 기준]
  - 카메라 1 (왼쪽 골대): 왼쪽 골대 정면 고정 촬영
  - 카메라 2 (센터): 경기 전체 촬영, AI 분석 기준 영상
  - 카메라 3 (오른쪽 골대): 오른쪽 골대 정면 고정 촬영

[하이라이트 클립 구조]
  득점이 감지될 때마다 아래 2개 클립을 순서대로 생성:

  클립 ① — 센터 카메라 | 빌드업 + 득점 순간
    - 구간: buildup_start ~ score_time + 1.0초
    - 속도: 1.0x (정상 속도)
    - 내용: 하프라인(또는 상대 골대)에서 시작해 득점 직후까지

  클립 ② — 골대쪽 카메라 | 리플레이 (슬로우 모션)
    - 구간: score_time - 2.0초 ~ score_time + 2.5초
    - 속도: 0.5x (슬로우 모션)
    - 내용: 슛 동작 + 골 인정 장면을 다른 각도에서 재생
    - 카메라 선택: goal_side 필드로 자동 결정
      · 'left'  → 왼쪽 골대 카메라 사용
      · 'right' → 오른쪽 골대 카메라 사용
      · 'unknown' → 설정된 골대 카메라 중 첫 번째 사용

[goal_side 감지 원리 (백엔드)]
  - 공의 포물선 정점(y 최솟값) 위치의 x 좌표로 판단
  - x < 0.40 → 화면 왼쪽 → 'left' 골대로 슛
  - x > 0.60 → 화면 오른쪽 → 'right' 골대로 슛
  - 0.40 ≤ x ≤ 0.60 → 'unknown' (센터 근처)

[카메라 역할 설정 UI]
  - AI 하이라이트 결과 패널에서 카메라 역할을 직접 지정 가능
  - 기본값: 카메라 0 → 왼쪽 골대, 카메라 1 → 센터, 카메라 2 → 오른쪽 골대
  - 카메라 역할이 설정되면 자동 멀티카메라 모드 동작
  - 역할 미설정 시 기존 방식(선택한 모든 카메라에 동일 구간 적용)으로 동작

[결과 영상 예시]
  득점 3회 경기 기준:
    ① 1번 득점 빌드업 (센터, 정상속도)
    ② 1번 득점 리플레이 (오른쪽 골대, 0.5x)
    ③ 2번 득점 빌드업 (센터, 정상속도)
    ④ 2번 득점 리플레이 (왼쪽 골대, 0.5x)
    ⑤ 3번 득점 빌드업 (센터, 정상속도)
    ⑥ 3번 득점 리플레이 (오른쪽 골대, 0.5x)

[하이라이트 응답 형식 변경사항]
  기존 필드에 추가:
    "goal_side": "left" | "right" | "unknown"  // 골 방향
    "replay_start": 43.3                        // 리플레이 시작 (score_time - 2.0)
    "replay_end": 47.8                          // 리플레이 종료 (score_time + 2.5)
